==============================================================
1. Lỗi 1: Permission denied khi chạy ./gradlew (không có bit thực thi)
==============================================================
Ghi chú về cách mô phỏng: thư mục bind-mount từ Windows luôn hiển thị file là 755 trong container,
nên ./gradlew chạy được và không tái hiện được lỗi. Để mô phỏng đúng thứ Git checkout trên runner
Linux (file được commit từ Windows có mode 100644), lệnh dưới sao chép dự án vào thư mục trong
container rồi đặt chmod 644 cho gradlew.

$ docker run --rm -v "$PWD:/src:ro" gradle:8.10-jdk21 sh -c "mkdir /work && cp -r /src/. /work/ \
    && cd /work && chmod 644 gradlew && ls -l gradlew && ./gradlew --version; echo exit_code=\$?"
-rw-r--r-- 1 root root 8762 Oct 12 20:02 gradlew
sh: 1: ./gradlew: Permission denied
exit_code=126

Giải thích: mã thoát 126 là "command found but not executable". Trên GitHub Actions bước này in
"##[error]Process completed with exit code 126." sau dòng "Permission denied".

==============================================================
3. Lỗi 3: build Docker Image với context và file không tồn tại
==============================================================
Trường hợp A: context ./app (thư mục không tồn tại), đúng như workflow hỏng.
$ docker buildx build -f ./docker/Dockerfile ./app
ERROR: failed to build: unable to prepare context: path "./app" not found
exit_code=1

$ docker build -f ./docker/Dockerfile ./app
ERROR: failed to build: unable to prepare context: path "./app" not found
exit_code=1

Trường hợp B: context là gốc repo nhưng file trỏ tới ./docker/Dockerfile (không tồn tại).
$ docker buildx build -f ./docker/Dockerfile .
ERROR: failed to build: resolve : GetFileAttributesEx docker: The system cannot find the file specified.

Ghi chú: lỗi ở trường hợp B do Docker client trên Windows in ra (GetFileAttributesEx là API của Windows).
Trên runner Linux của GitHub Actions, thông điệp dự kiến có dạng "failed to read dockerfile: open
docker/Dockerfile: no such file or directory"; log thật sẽ do người điều phối bổ sung trong
troubleshooting.md.
